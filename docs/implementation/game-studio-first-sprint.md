# Game studio implementation plan for the first sprint

**Outcome.** A newly formed team can turn an approved game idea into a staffed, populated, Active Sprint 1 and an accepted worker claim on its first implementation task. A retained team can reach that same point by using work it already produced. The Producer owns this outcome. The platform owns the records that establish what has happened and who is authorized to act.

For fresh work, its board Story is visible as a non-executable draft during refinement. The UI can show a pending contribution before a retained Story is published. **Result selection.** A logical increment can survive renewed sessions, an installation update and revised planning evidence. An old result is eligible for review only when the original request and target’s final artifact match the same board, participants, accepted package and Story. Verify the outline, artifact type, digest and original request basis from the records. Compare newer direction separately. A later hold may restrict publication or execution while leaving the recovered work suitable for review. Prefer an already admitted matching result, then one uniquely valid returned result. Distinct incompatible proposals require a recorded selection or correction by the accountable owner. A newer timestamp or a free-text title is insufficient. Replay after a timeout reuses the recorded effect and resumes at the first missing child.

### How the Producer resumes a stalled contribution

On a wake, reconnect or due retry, Gabriel reads the current increment and checks his authority. The following order applies within that increment. A resource or staffing change can still advance other authorized work.

| What Gabriel finds | What happens next |
|---|---|
| A matching accepted publication or a valid returned proposal | Reuse the publication or bind the returned result. Reconcile any missing children when admission is authorized. Record new evidence even when a hold requires Marcus’s disposition. Cancel any pending generation retry for this request. |
| No valid result and an attempt is already running | Keep the attempt ID and the expected wake. Reconnect discovery can find its result if the completion notification is lost. |
| A failed attempt with a correctable diagnostic, remaining budget and authority to request refinement | Persist the next attempt number and due time on the original increment. When due, reread for a late success or new hold. If still eligible, issue one idempotent specialist request bound to the original Story and latest applicable inputs. Include the failing fields. Use the authorized contribution request path. The existing Communications retry command is reserved to a human manager. |
| A hold on the proposed action, a non-retryable fault, or an exhausted budget | Record the specific condition, the person with authority or ability to resolve it, and the evidence that will wake the work. Notify that owner once per material change. A timer cannot lift a hold or reset the attempt budget. |

The platform checks the increment revision when reserving an attempt. Redelivery or a restart reuses the same attempt and command key. The targeted fresh regression must see one failed request followed by one automatic replacement. The retained regression must see zero replacement requests after the valid result is available.
