This is an implementation checkpoint, not a completed compute rollout. The active objective remains the full generic compute architecture in [the migration map](compute-migration.md).

## Signed provider-result ingress checkpoint

The runtime can sign an enrolled provider observation without rewriting its observed time, sequence, scope or teardown claim. Signing requires the configured P-256 certificate to remain valid through the observation expiry. Core accepts bounded HTTPS JSON at `/api/compute/providers/results`, verifies the existing node signature and reconciliation rules, and returns operation, sequence, exact payload digest and whether the result was applied only after reconciliation completes. Identical replay is acknowledged without another state transition. The route shares the bounded provider ingress rate policy; HTTP, encoded bodies, oversized bodies and invalid signatures are rejected.

## Durable lifecycle-observation checkpoint

Provider journal version 4 now commits resource identity, a monotonic per-operation result sequence and the pending lifecycle result together under the existing physical-operation lock. A new physical observation replaces the pending observation for that operation; sequence history remains after acknowledgement. A late acknowledgement cannot remove a newer replacement, and an exact sequence requires the exact payload digest. Result timestamps are fixed at observation and never refreshed by journal reads. Reservations remain held.

The Hyper-V executor now records conservative lifecycle observations: a created/off VM is provisioning, a running VM is bootstrapping, stop can report stopped, and destroy remains destroying pending certified storage teardown. VM absence alone never claims teardown. Backend effects that throw still leave the durable execution claim for observation-only recovery; they do not fabricate successful results.

Validation: seven new cases cover restart, replacement and acknowledgement races, monotonic sequence after acknowledgement, concurrent journal writers with one execution claim, cancellation after effect completion, invalid evidence, failed post-effect persistence with observation-only recovery, conservative executor integration, and rejection of version 3 without resetting history. The expanded affected suite passed 251 tests with seven optional PostgreSQL tests skipped. The SDK NU1902 warning remains. No live VM, service, database migration or deployment was changed.

Required continuation: connect the outbox to signed HTTPS delivery and its supervised worker; handle expired results through fresh authorized physical observations without starving other queued results; complete dispatch transport, readiness, certified teardown and the remaining original migration scope. The unpublished journal rejects versions 1–3; no deployed history was migrated.

## Bounded result-outbox dispatch checkpoint

Added a result dispatcher that reads at most 100 pending observations per pass using a stable operation-ID cursor. Delivery occurs outside the physical journal lock; only the exact returned operation/sequence/digest can acknowledge a row. Failed delivery retains evidence, and a new observation racing an old acknowledgement remains pending. Expired observations are retained unchanged and returned as requiring fresh observation authority. A cursor allows subsequent pages to proceed past expired evidence.

Validation: five new cases cover lost acknowledgement, delivery without the physical lock, expiry retention, acknowledgement mismatch, observation/acknowledgement races and a full page of 100 expired operations followed by fresh evidence. The initial paging fixture incorrectly included execution grants in an observation-only packet and was rejected by the verifier; corrected the fixture, preserving the protocol restriction. Final expanded affected suite: 256 passed, seven optional PostgreSQL tests skipped. SDK NU1902 warning unchanged. No live infrastructure changed.

Required continuation: production signing/client composition, supervised result-delivery scheduling with bounded backoff/cursor recovery, fresh authorized observations for expired evidence, and the remaining provider and retirement roadmap. The dispatcher is a bounded pass, not an installed delivery service.
