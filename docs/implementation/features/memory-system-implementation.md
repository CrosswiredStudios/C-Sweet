## 2. Completion rules

Every work package needs implementation, appropriate regression evidence, operational recovery behavior, and a short acceptance record. A library test, a package build or a completed code change alone does not close a product outcome.

Maintain these constraints throughout:

- The server owns identity, source attribution, trust transitions and current audience authorization. Agents and model output cannot authorize themselves.
- Every derivative preserves contributor fingerprints, audience restrictions, sensitivity, validity and retention dependencies. Evidence integrity, recall eligibility and permission to inspect retained evidence are distinct checks.
- Accepted effects and their notification outbox commit atomically. Events are wake hints; authorized current-state reads and bounded discovery support offline, duplicate and missed-event recovery.
- Durable job generations, immutable accepted output and fenced leases remain authoritative. Model calls occur outside short database transactions.
- Suppression, revocation, expiry and forgetting apply before content reaches any model/provider or external consumer. Availability fallback must never turn a policy denial into a content release.
- Deletion prevents restoration by queued jobs, replay, reconnect, caches or backfill. Active legal holds preserve required evidence without making it eligible for recall.
- Lasting employee memory and transient model context are distinct. Naomi must remember relevant facts between conversations and carry a user's authorized instructions into work with producers/developers. Preserve source attribution and current access restrictions; unrelated private conversation details do not become shared merely because the same employee remembers them.
- Isolate transient context by authorized work item and attempt rather than treating normal memory access as a reason to stop the employee runtime. Build each model request from that context and reauthorize its evidence before dispatch and retry. Completed reads remain audit evidence, not implicit prompt inputs. Current invalidation and legacy runtimes can still require replacement. Recover the business operation from current durable state; previously committed effects must remain idempotent.
- Record content-free diagnostics by default. Memory text is untrusted evidence, not instructions or an execution grant.
- Public contract/package changes follow semantic versioning and the cross-repository rules in `AGENTS.md`. Changed packages must be tested, packed and verified in consumers with sibling references disabled.
