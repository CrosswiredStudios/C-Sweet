`HyperVComputeDriver` supports `None` and `OutboundOnly`. The latter uses the installed development NAT switch, one fixed adapter, stateful public IPv4 egress and fixed private/metadata destination blocks with narrowly scoped resolver/DHCP exceptions. The agent supplies no host switch, interface or command. Other network modes remain unsupported. `ComputeDispatchVerifier`, `ComputeBroker.SubmitWorkloadAsync` and `ComputeDispatchAuthorizer` require independent current outbound authority for ordinary commands and previews on a networked VM. Preview port limits apply to their separate inbound/publish grants; an outbound grant does not grant publication. New instance-bound preview constraints accept the VM's network specification without becoming an outbound-action grant. The fixed switch is a development-host option; arbitrary host routing, public endpoints and provider-agnostic network management are outside this change. Hyper-V's [extended ACL documentation](https://learn.microsoft.com/en-us/powershell/module/hyper-v/add-vmnetworkadapterextendedacl?view=windowsserver2025-ps) documents the stateful rules and priority ordering.

## Authority and execution

`ComputeBroker.SubmitWorkloadAsync`, `ComputeDispatchAuthorizer` and `ComputeDispatchVerifier` require independent `compute.execute.v1` and `network.outbound.v1` authority for managed restore. Installation declarations do not grant access. `ComputeGrantConstraints.AllowedDependencyRegistries` permits a registry-limited grant; such a grant cannot authorize an outbound-network VM. A broader existing outbound grant may cover the fixed registry operation. Environment, organization, installation, project, current revision, expiration and resource constraints remain enforced independently for each contributing grant.

`ComputeDependencyAccess.AuthorizeAsync` requires a current enrolled-node proof and the exact in-flight operation. It rechecks the current generation, lease, desired state, installation and recorded grant identities/revisions. `ComputeNodeDependencyInstaller` checks this permission before each download, after verification, during large transfers, before populating the guest cache and before the requested command. Revocation, ownership/generation drift and unavailable authorization stop further work. Grant edits save their notification outbox with the grant/audit changes; compute events remain wake hints rather than authority.

The provider fetches only public-registry HTTPS tarballs, rejects redirects, proxy use, credentials, private/host/metadata DNS answers, oversized responses and hash mismatches. Each package is bounded to 32 MiB, the set to 256 packages/192 MiB and execution to seven minutes. Host code never unpacks or executes package contents. Verified bytes cross the existing owned-VM guest-command channel using fixed 18,000-byte block offsets. A fresh operation may reuse a retained guest tarball only after downloading and verifying the pinned registry bytes again and checking the guest file's exact length and SHA-512 under current authority. Partial, changed or symbolic-link files cannot pass that check. npm populates its content cache inside the guest with no network, then `RestoreScript` checks the actual source ZIP and lockfile and runs `npm ci --offline` against that cache.

`ComputeReplayJournal` retains its physical execution fence. Lost/unknown command outcomes cannot blindly replay. The dispatch reservation covers the bounded managed operation while its short-lived signed admission and fresh grant checks remain separate. Existing command/publication serialization stays byte-compatible when the optional dependency field is absent, preserving prior request and signature digests.
