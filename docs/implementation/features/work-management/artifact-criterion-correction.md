SDK 4.6.4 separates the exact acceptance-criterion array from requirements in the prompt. Requirements and checklist details are still evaluated in summary, evidence and findings; they cannot become additional criterion identities. `ArtifactDeliveryReview.Validate` returns combined field-specific errors for artifact/revision/hash identity, missing or extra criterion text, empty evidence and contradictory verdict/findings. It never rewrites a criterion, removes a finding or changes a verdict.

`TechnicalReviewJson.ReadAsync` supplies strict structured JSON, a 128,000-character response bound, 16,000-character summary/evidence bounds and at most three corrections. Artifact reviews request 128,000 output tokens within the configured provider ceiling. Only the latest invalid response is included in a correction turn, avoiding accumulating large responses. Exhaustion names a C-Sweet artifact-QA processing issue for management and returns no accepted verdict. Existing technical-review callers retain their output-token setting.

Before returning a valid verdict, `ArtifactDeliveryReview.ExecuteAsync` rereads current planning and the assigned reviewer and reauthorizes the exact document revision, checking its content digest again. Planning changes, revoked access or changed content prevent acceptance. A valid negative review still returns `changes_requested` with genuine actionable findings.
