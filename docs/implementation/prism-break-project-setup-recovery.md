## Corrections

- `AgentCoordinationService.SameArtifact` compares the structured artifact metadata
  and JSON value as well as message text. Changed proposals and pages can continue;
  identical evidence, including JSON-only reformatting, remains a loop. Profile
  validation, speaker authorization, revision ordering and idempotent replay remain
  required.
- `WorkItemMutationEngine.RequeueAsync` leaves an agent's own repeated-failure stop
  blocked on routine self-requeues. The current reporting manager or authorized
  human can still explicitly retry after review. No replacement wake or revision
  is generated by the suppressed self-requeue.
- `AgentTicketFeedback.RecordFailureAsync` reuses an outstanding notification for
  the same ticket and recipient across delivery keys. Its action follows the
  current escalation chat. `CSweetDbContext.CaptureApplicationNotificationEvents`
  publishes an update when that action changes.
- Producer **4.0.16** permits descriptive `ProfileData` corrections in its draft and
  explains that draft-response fields are distinct from the complete submitted
  command. Identity, team, profile selection, exact evidence, budget, authority and
  previously submitted command identities are preserved. Missed-event revision
  recovery rereads the exact accepted documents, not only the feedback.

## Streaming persistence batching, October 24

`ModelStreamCoalescer.ReadAsync` now batches eligible plain `TextReasoningContent`
as well as plain `TextContent`, preserving their distinct kinds and exact ordered
content. The first update remains immediate; subsequent batches flush at 32
fragments, 4,096 characters, a 500 ms elapsed check between provider updates, or a
content/response/message/role/model/author boundary. Protected reasoning,
annotations, additional metadata, tools, usage and terminal updates are forwarded
unchanged after flushing prior plain fragments. Buffered content is flushed before
provider failure or cancellation. No prompt, accepted requirement or review gate is
removed by this transport optimization.

`PlatformLlmCapabilityHandler.PersistStreamAuditAsync` retains the same outbox
receipt across up to three synchronous save attempts. Every batch must be saved
before forwarding; persistent failure terminates the stream with retryable
`llm.audit_persistence_failed` instead of releasing unaudited content. Successful
receipts still detach from the long-lived context only after persistence, preserving
bounded tracking and durable outbox delivery.
